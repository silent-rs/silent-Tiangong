# ReAct Loop 与总结阶段分离架构重构 — 需求文档

> 创建时间：2025-07-14
>
> 状态：需求定稿

## 1. 要解决的问题

当前 ReAct Loop 将工具执行和最终回复混在同一个循环中，导致以下问题：

### 1.1 Loop 异常中断与瞎猜

LLM 执行完任务后输出总结或向用户提问时，系统使用 lite 模型检测"完成度"。lite 模型判定不可靠：

- **假阴性**：LLM 已给出完整总结，lite 模型判为 INCOMPLETE → 注入 system-reminder → LLM 被迫继续找事做 → 瞎猜
- **假阳性**：LLM 在循环中编造了看似实质的内容，lite 模型判为 COMPLETE → 输出不准确结论

### 1.2 无法区分过程消息和最终回复

前端无法判断 LLM 的哪段文本是"过程说明"哪段是"最终回复"，导致：

- 所有文本都提供复制按钮（包括中间过程的无意义输出）
- 用户无法快速定位最终回复
- 消息列表混乱

### 1.3 简单问答有额外开销

用户说"你好"时，LLM 第一轮不返回 tool_calls，但系统仍需调用 lite 模型做完成度检测，产生不必要的延迟和 token 消耗。

### 1.4 INCOMPLETE 提示消息误导 LLM

当 lite 模型判定 INCOMPLETE 时，注入的 system-reminder 只说"被判定为未完成"，没有指出具体缺什么。LLM 收到后不知道该做什么，只能瞎猜。

## 2. 用户可感知的变化

### 2.1 对话体验

- LLM 执行完任务后不再出现"瞎猜"现象（重复工具调用、编造额外步骤）
- LLM 向用户提问后能正常结束循环，等待用户回复
- 简单问答响应更快（无 lite 模型检测延迟）

### 2.2 前端展示

- ReAct Loop 中的工具调用、中间推理、过程文本：紧凑展示，不提供复制按钮
- 最终总结回复：作为主消息展示，提供复制按钮
- 可选：展示阶段切换状态（"正在执行..."→"正在总结..."）

## 3. 必须满足的行为

### 3.1 Loop 终止

- LLM 完成所有工具调用后，进入独立的总结阶段
- 总结阶段由主模型（非 lite 模型）判断任务是否完成
- 任务完成 → 输出最终回复，结束
- 任务未完成 → 重新进入 ReAct Loop 继续执行
- 需要用户提供额外信息 → 输出提问，结束
- 简单问答（无需工具）→ 直接进入总结阶段输出回复

### 3.2 循环控制

- 总结→重入 Loop 的最大次数有上限（建议 3 次）
- 每次 Loop 内的工具调用轮次有上限（建议 15 轮）
- 超限时强制进入总结阶段，给出基于已有结果的最终回复

### 3.3 消息分层

- 前端能区分"过程消息"和"最终回复"
- 最终回复有独立的 message_id，支持复制
- 过程消息不提供复制按钮

### 3.4 兼容性

- Sub Agent 的 `execute_turn` 同样适用新架构
- 上下文压缩机制不受影响
- 取消/消息注入/审批等现有命令通道不受影响

## 4. 明确不做

- 不改变现有的工具执行机制（权限、审批、失败恢复等保持不变）
- 不改变上下文压缩策略
- 不引入新的外部依赖
- 不改变 Session 持久化格式（新增字段需向后兼容）
- 不改变 MCP / Plugin / Skill 系统

## 5. 异常与边界

### 5.1 LLM 未按约定输出标记

LLM 可能不输出约定的阶段切换标记（如 `<<SUMMARIZE>>`）。系统必须有兜底：

- ReAct Loop 中 LLM 无 tool_calls 且无标记 → 隐式触发总结
- 总结阶段无重入标记 → 视为任务完成

### 5.2 总结→重入 Loop 的上下文膨胀

多次重入会导致上下文快速膨胀。需要：

- 重入时注入"上轮总结"精简上下文
- 利用现有上下文压缩机制

### 5.3 Sub Agent 场景

Sub Agent 使用相同的 `execute_turn`，需要确保：

- Sub Agent 能正确进入总结阶段
- Sub Agent 的总结结果能正确回传给主 Agent

### 5.4 流式输出连续性

总结阶段的流式输出不能中断，前端不能出现"闪烁"或"重置"。

## 6. 与已有系统的关系

| 现有模块 | 关系 |
|----------|------|
| `ReactEngine::execute_turn` | 核心重构对象 |
| `check_completion_with_lite_model` | 移除，由主模型总结阶段替代 |
| `force_final_response` | 保留，作为超限兜底，改进 prompt |
| `StreamEvent` | 新增事件类型或标记 |
| 上下文压缩 | 不受影响，继续在 Loop 内运行 |
| Sub Agent | 需适配新架构 |
| 前端消息渲染 | 需适配新的消息分层 |
