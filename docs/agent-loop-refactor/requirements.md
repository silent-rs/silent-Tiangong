# Agent 执行核心重构 — 需求与行为契约

## 1. 背景

`crates/tiangong-core/src/react/execute.rs` 已超过 4000 行，当前 Agent 执行阶段由 `next_step`、多个活动任务 `Option`、工具任务集合和多套计数共同表达。模型、工具、审批、压缩、完成度检查、运行中引导消息、插件反馈和暂定完成命令彼此交错，新增一种输入时需要同时检查大量组合状态。

本次工作不再只做局部状态机替换，而是对 **Agent 执行核心**进行分阶段大重构：先冻结行为契约和安全网，再建立单一事件循环与单一阶段状态，随后解决终态封口、迟到结果、完成度策略、模块边界和可观测性。

## 2. 总体目标

- 用一个事件循环驱动模型、工具、审批、压缩、命令与完成度检查。
- 用单一 `ExecutionPhase` 表达当前阶段，使无效活动组合尽量不可表达。
- 用统一 `ExecutionBudget` 表达执行预算，消除“内外双层循环”的控制概念。
- 用统一命令入口和终态封口保证：命令要么由当前 turn 处理，要么可靠进入下一 turn，不能确认成功后丢失。
- 保持插件生命周期、消息协议、用量统计和流事件契约可验证。
- 将 Summary 从“外层循环”收敛为完成度策略，并在结构稳定后评估按需调用。
- 把核心执行文件拆成职责清晰、可独立测试的模块。

## 3. 需求编号

### 3.1 架构需求

- **ALR-001 单一阶段**：任意时刻只有一个执行阶段，阶段直接持有该阶段所需活动资源。
- **ALR-002 单事件循环**：命令、模型结果、工具结果、压缩结果和同步推进都由同一驱动循环处理。
- **ALR-003 统一预算**：模型请求编号、阶段轮数、完成度续作次数和工具执行标记由 `ExecutionBudget` 管理。
- **ALR-004 显式迁移**：每个事件都产生可审查的阶段迁移，不依赖多个字段组合推断真实阶段。
- **ALR-005 模块边界**：阶段、命令、模型、工具、压缩、完成度、终态门控和 turn 提交职责分离。

### 3.2 行为需求

- **ALR-101 引导消息重启**：运行中用户消息中断当前 Agent Loop 直接拥有的模型、工具等待、压缩和审批，消息成功落盘后在同一物理 turn 内从新意图继续执行。
- **ALR-102 预算重置**：新用户意图重置阶段预算和工具去重记录，但保留物理 turn 的累计用量。
- **ALR-103 插件后台保持**：普通引导消息不取消子 Agent、浏览器观察、终端监听等插件独立后台任务；显式取消整个 turn 才调用 `on_cancel`。
- **ALR-104 Summary 中断**：被引导消息中断的 Summary 部分输出只能作为过程消息，不得作为最终回复。
- **ALR-105 暂定完成可撤销**：唯一终态提交前，用户消息、有效工具注入和有效审批可撤销暂定结果并继续执行。
- **ALR-106 控制命令完整处理**：暂定完成阶段不得吞掉 Cancel、Shutdown、标题、配置、用量、插件事件或审批命令。
- **ALR-107 最新消息锚点**：最终成功、失败、取消状态及耗时写入最新用户消息；生命周期范围仍以物理 turn 起点为准。
- **ALR-108 生命周期唯一**：一个物理 turn 只调用一次 `on_turn_started` 和一次 `on_turn_finished`。
- **ALR-109 唯一终态**：一个物理 turn 只发布一次 `Done` 或 `Error`。
- **ALR-110 工具协议完整**：中断、取消和异常迁移都必须闭合 Provider tool call/result 协议。
- **ALR-111 用量权威**：最终终态和 Session 使用封口前最新累计用量，不得冻结为过期快照。

### 3.3 并发与可靠性需求

- **ALR-201 原子封口**：当前 turn 从接受命令切换到提交终态时必须有明确原子边界。
- **ALR-202 可靠投递**：用户消息只有在当前 turn 成功保存，或可靠进入下一 turn 队列后，才能向调用方确认成功。
- **ALR-203 顺序保持**：封口前已接受的命令按入队顺序处理；Cancel/Shutdown 等决定性命令不得被较早的重启意图覆盖。
- **ALR-204 迟到结果安全**：旧阶段异步结果不得推进新意图；但工具副作用、协议闭合、审计和用量不能因“结果过期”被无条件丢弃。
- **ALR-205 无半迁移状态**：阶段迁移失败时不得留下已取出资源却没有新阶段接管的状态。

### 3.4 可观测性与演进需求

- **ALR-301 迁移可观测**：关键阶段迁移、执行预算、意图代际和终态封口可通过结构化日志诊断。
- **ALR-302 事件契约保护**：重构前后关键流事件顺序通过自动化测试保护。
- **ALR-303 完成度策略可替换**：Summary/ForceFinal 从驱动循环中解耦为 `CompletionPolicy`，先保持行为，再评估按需 Summary。
- **ALR-304 可回滚**：每个开发任务可独立审查、验证和回滚，不允许跨多个高风险阶段积累未验证改动。

## 4. 行为基线与已知问题

“行为保持”只指下表中的目标契约，不表示复制当前所有缺陷。

| 场景 | 当前基线 | 目标行为 | 处理任务 |
| --- | --- | --- | --- |
| 运行中用户引导 | 同 turn 中断并重启 | 保持，并由状态机表达 | 04B/04C/04D/04E |
| PendingFinish + Cancel | 已统一处理为取消 | 保持 | 04E |
| PendingFinish + InjectTool | 当前只进入缓冲，可能提交旧结果 | 撤销暂定结果并重新分析 | 04E |
| PendingFinish + ReportUsage | 当前暂定结果可能冻结旧用量 | 最终使用最新累计用量 | 04E |
| 仲裁后新消息 | 存在写入无人消费通道窗口 | 当前处理或可靠转入下一 turn | 05 |
| Summary 被引导中断 | 降级为 ReAct 过程消息 | 保持 | 04B |
| 插件独立后台任务 | 引导时继续运行 | 保持 | 01/04E |
| 最终消息状态 | 写入最新用户消息 | 保持 | 01/09 |
| 独立 Summary 请求 | 当前按既有规则触发 | 结构迁移期保持；后续按指标决定是否减少 | 08 |

## 5. 状态机不变量

1. 任意时刻只存在一个 `ExecutionPhase`。
2. `WaitingApproval` 必须同时持有待审批工具和所属工具批次。
3. `WaitingTools` 中任务集合与运行记录必须一一对应。
4. `PendingFinish` 不得持有主循环直接拥有的活动模型、工具或压缩任务。
5. 用户消息只有成功落盘或可靠排入下一 turn 后才确认。
6. 新用户意图重置执行预算，不重置物理 turn 累计用量。
7. 中断工具调用后，每个 Provider tool call 都有对应结果或被安全移除。
8. Summary 中断产生的部分输出不能保持最终 Summary 身份。
9. 物理 turn 只发布一次终态，只执行一次开始和结束生命周期。
10. 封口前接受的命令全部处理；封口后的命令不得写入旧队列。
11. 旧意图结果不能推进新阶段，但必要的工具结果、审计和用量必须按规则归档。
12. 任何阶段迁移都必须明确转移、取消或完成旧阶段持有的资源。

## 6. 范围

### 6.1 本次做

- Agent Loop 单阶段状态机和单事件循环。
- 执行预算统一。
- 模型、工具、审批、压缩、完成度和命令处理迁移。
- 当前 turn 命令入口与终态封口。
- 迟到结果与结构化取消策略。
- Summary/ForceFinal 完成度策略解耦及按需调用评估。
- 核心模块拆分、迁移日志、回归测试和真实场景验证。
- 必要的 core 内部接口与 `PluginFeedbackTx` 入口适配。

### 6.2 不做

- 改变权限模型本身。
- 改变 Session 落盘格式。
- 重写 LLM Provider 客户端。
- 重写插件业务实现或默认取消插件后台任务。
- 与执行核心无关的前端视觉重构。
- 在同一任务中同时进行状态机迁移和无关性能优化。

## 7. 完成标准

- 所有 ALR 需求均有设计落点、实现任务和自动化验证。
- `execute_turn` 不再使用 `next_step` 与并列活动 `Option` 推断阶段。
- 终态封口不存在“确认成功但消息未处理”的路径。
- 当前行为契约与明确修复目标全部通过测试。
- Summary 简化有实测依据、开关或回滚路径，不以主观判断直接替换生产行为。
- 完整 Rust 检查、核心测试、相关插件测试和真实交互验证通过。
