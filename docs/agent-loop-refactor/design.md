# Agent 执行核心设计 — 单循环 + 直启（v2）

> 2026-08-16 修订：本文档取代同日的"统一通道设计"定稿。评审结论：常驻 Driver
> 消除的竞争窗口在产品主场景（一对一 Core/会话、界面输入天然串行）中几乎不可
> 触发，其代价（Inbox 调度层、running 标志、终态暂存仲裁）超出收益，整体移除。
> 本次重构的核心目的不变：**完成引导消息的处理，并将 Agent Loop 收敛为单循环**。

## 1. 总体形态

一句话概括：**空闲起轮、运行中投通道；每轮一个任务、任务持有 TurnContext。**

```
外部输入（GUI / CLI / Server / 插件）→ deliver
  用户消息：
    会话运行中 → send_command 注入活跃 turn 的命令通道 → turn 内引导
    （中断当前模型/工具/审批 → 保存新消息 → 从新意图重启，模型自主决策）
    会话空闲   → Core 直接起轮：build_turn_context（磁盘最新）→ 保存消息
    → 发确认 → spawn turn task（通道随任务创建，任务结束通道关闭）
  工具注入：运行中投通道；空闲写入会话延迟队列（下一轮请求自动携带）
  审批响应：仅运行中投通道，空闲拒绝
  取消/配置：就地更新共享状态，运行中另投通道同步活跃 turn
```

## 2. 关键组件

| 组件 | 职责 |
| --- | --- |
| `TiangongCore` | 会话级材料唯一持有者：构建每轮上下文、空闲起轮、空闲期维护（压缩/清空/标题/配置）、关闭 |
| `shared_runtime::TurnTask 注册表` | session_id → { 通道发送端, 任务句柄, 代际 }；`is_running` = 任务存活；双检 + 代际防误删（与 v0.14.x 线上版本同构） |
| turn task | 持有 `TurnContext` + 命令接收端，跑 `run_turn`；终态在收尾内部发布（每轮独立 Done） |
| `PluginFeedbackTx` | 插件反馈直连 turn 命令通道发送端；任务结束通道关闭，迟到反馈发送失败（天然封口，无需租约） |

## 3. 引导消息处理（本次重构的核心交付）

1. **turn 进行中**收到用户消息（`react/command.rs`）：中断当前活动
   （模型流/工具批次/审批等待/暂定提交均可撤销），校验并保存消息，
   成功才向界面确认，随后从新意图重启循环；不触发插件 `on_cancel`
   （仅显式取消触发）。
2. **turn 收尾窗口**（结果已提交、正在落盘）收到用户消息：turn 的
   收尾排空（`core/mod.rs` start_user_turn wrapper）drain 通道残余——
   全部保存不丢，**最后一条接续起轮**（与引导"以最新意图为准"一致），
   其余作为会话历史保留。
3. **手动压缩期间**收到用户消息：取消压缩（未应用任何结果）并立即起轮；
   压缩可随时重新发起。压缩期间到达的标题/配置类命令就地应用。
4. 终态锚点（ALR-107）：结果写入**提交时最新**的用户消息——引导后新意图
   是锚点，原始消息保留无终态。

## 4. 已删除的机制（相对"统一通道"版）

| 机制 | 取代方式 |
| --- | --- |
| 常驻 Driver（drive_agent）与 Inbox（react/inbox.rs） | 空闲起轮 + 运行中投通道 |
| running 标志（投递置位/收尾清零） | `is_running` = 注册表任务存活 |
| 终态暂存仲裁（try_recv_or_finish，"避免中间终态"） | 每轮独立终态，turn 收尾内部发布；连续轮次各自 Done |
| 压缩 ConsumeLocally/defer 排队策略 | 压缩被用户消息取消并立即起轮（Relay） |
| 插件反馈封口租约（ActivityLease） | 通道随 turn 生灭，迟到反馈发送即失败 |
| 关闭排空（persist_pending_on_shutdown） | turn 收尾排空统一覆盖（保存不丢 + 最后一条续轮） |
| `TiangongCore` 的 Drop 发送关闭 | Drop 空操作：任务自然跑完落盘；显式关闭走 `shutdown_join`（cancel_and_join）/ CoreManager |

## 5. 保留的既有原则

- 每轮从最新磁盘 Session 与最新配置构建 `TurnContext`，禁止提前构造快照（ALR-201/204）。
- 消息保存成功才向界面确认（ALR-202）。
- 命令按接收顺序处理（ALR-203）：单通道 per-turn FIFO + 收尾排空按序保存。
- 单循环 Agent Loop：无工具调用的响应即候选完成，模型自主决策（不再有
  Summary/最终回复的强制第二循环）。
- 进程级共享 multi-thread runtime（`block_in_place` 依赖），所有 turn task 共跑其上。

## 6. 已知取舍

- **收尾窗口的启动竞争**由 `spawn_turn` 双检兜底（查表 + 撞车 abort + oneshot
  启动门），与 v0.14.x 线上行为一致；窗口为毫秒级。
- 连续消息只有最后一条被接续执行，其余保存为历史（与引导语义一致，用户可重发）。
- 关闭时通道残余消息保存但不起轮（等待用户下次输入）。
