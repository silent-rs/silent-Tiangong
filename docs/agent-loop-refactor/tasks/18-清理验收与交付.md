## 交付后修复（Review 追加）

- **手动压缩期间的引导消息/工具注入丢失**（从旧实现继承的窗口缺陷）：`ConsumeLocally` 命令策略对 `InjectUserMessage`/`InjectTool` 原为忽略丢弃。修正语义（Review）：压缩是独立维护活动，不因新输入让路——新输入经 `defer_input` 回调即时转入 Inbox 排队，**压缩继续完成并应用结果**，随后同一 driver 自动处理排队消息；只有终止类命令（取消/关闭）或转排队失败（会话关闭）才取消压缩。守护测试：`steer_during_manual_compression_defers_to_next_turn`（断言消息顺延执行且压缩未被取消）。
- **手动压缩的 system prompt 防御性重建**：裸 session 直接手动压缩时 `system_prompt_message` 可能缺失导致压缩请求构建失败，`run_manual_compression` 现在构建后重建（真实场景 turn 后的 session 均已具备，此为防御）。
