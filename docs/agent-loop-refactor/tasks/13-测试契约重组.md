# 任务 13：测试契约重组

> 需求：[../requirements.md](../requirements.md) §5 ｜设计：[../design.md](../design.md) §11
>
> 状态：**已完成**（不含生产行为改动）｜对应方案阶段 1。

## 目标

1. 把现有测试从"保护旧内部流程"改为"保护真实用户行为"：全部测试按**永久保留 / 按新架构改写 / 删除或迁移**分类。
2. 补齐 Inbox、单 driver、最新 Session、关闭可靠性与工具漏调用的**失败用例**，作为任务 14/15 的安全网。
3. 本任务不改变任何生产行为。

## 实施结果

- 新增 `crates/tiangong-core/src/react/contract_tests.rs`：工具义务与候选完成门控契约测试（5 项，1 项当前绿色锚点 + 4 项 `#[ignore]` 失败用例）。
- 新增 `crates/tiangong-core/src/core/contract_tests.rs`：Inbox / 单 driver / 最新 Session / 关闭可靠性契约测试（4 项 `#[ignore]` 失败用例），针对 `TiangongCore::deliver` 公开边界。
- 失败用例统一以 `#[ignore = "任务 14/15：…实现后启用"]` 标注，保持主测试套件绿色；任务 14/15 实现后移除标注必须转绿。

### ignore 策略说明

失败用例在当前实现上必然失败（这正是它们的价值），直接提交会破坏"每个提交保持绿色"的分支策略。因此用 `#[ignore]` 挂起：

- 主套件 `cargo test -p tiangong-core` 保持绿色；
- `cargo test -p tiangong-core contract_tests -- --ignored` 可随时核对失败形态（见下方记录）；
- 对应能力实现后移除 ignore，测试必须转绿，防止实现偏离契约。

## 新增失败用例与暴露的缺陷

| 用例 | 契约 | 当前实现暴露的缺陷 |
| --- | --- | --- |
| `rapid_followups_execute_as_separate_turns` | ALR-101/104 | 空闲连发 3 条消息被并入同一轮，仅 1 条获得 turn 终态 |
| `sealed_next_turn_reads_latest_session` | ALR-201/204 | 封口交接提前构建旧 Session 快照，前一 turn 最终消息对下一轮模型请求不可见 |
| `shutdown_does_not_silently_drop_accepted_message` | ALR-202/206 | 关闭静默清空已接受队列（磁盘无消息且返回 Ok），或竞态在关闭后启动新 turn 并发出模型请求 |
| `idle_tool_injection_accepted_without_wake` | ALR-102/106 | 空闲期工具注入直接 `Err(WorkerStopped)`，内容丢失 |
| `attachment_request_rejects_text_only_completion` | ALR-003/006 | 附件义务未满足时纯文本被发布为成功终态 |
| `attachment_obligation_repair_recovers_with_tool_call` | ALR-007/008 | 模型第二次返回 tool call 时被 Summary 阶段吞掉，read_file 从未执行 |
| `attachment_obligation_repair_exhaustion_fails_explicitly` | ALR-008/009 | 连续漏发工具仍返回 Success（当前实现: Success） |
| `failed_tool_result_does_not_satisfy_obligation` | ALR-307 | 工具失败 + 模型声称完成 → 虚假成功 |
| `plain_question_without_obligation_completes_without_tool` | ALR-006 反向 | **当前绿色锚点**：普通问答直接完成且不强制工具，新架构不得破坏 |

义务来源采用宿主附件管线的真实形态：`Text + AssetReference + ModelInstruction`（`tiangong-media-archive/attachment.rs` 的文件附件输出），属于 ALR-006 第一级"入口显式声明"，不依赖自然语言分类。
