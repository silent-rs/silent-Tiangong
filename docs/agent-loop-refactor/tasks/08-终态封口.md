# 08 - 终态封口与下一 Turn 交接

## 目标

建立当前 turn 命令接收与最终提交的原子边界，消除“命令写入成功但无人消费”，并让封口后的用户消息可靠进入下一 turn。

## 范围

- `shared_runtime.rs`
- core 命令入口与 `PluginFeedbackTx`
- `react/ingress.rs`（可新增）
- turn 提交边界

## 任务

1. 实现 `CommandIngress` 与 `Accepting / Sealing / Committing`。
2. 所有命令来源统一经过 ingress，不允许持有可绕过门控的裸发送端。
3. `PendingFinish` 原子进入 Sealing，排空封口前命令；需要继续时恢复 Accepting。
4. 成功封口后进入 Committing，旧队列拒绝新命令。
5. 用户消息在 Committing 时可靠排入下一 turn，或返回明确的交接结果；不能虚报成功。
6. 消息确认基于成功落盘或可靠排队，不基于 mpsc send。
7. 处理关闭、panic、Core 替换、旧代消费者和附件所有权。
8. 添加可控屏障的并发测试，覆盖封口前后投递。

## 不做

- 不改变执行阶段业务逻辑。
- 不通过增加任意 sleep 规避竞态。

## 验收

- 无确认成功后丢消息路径。
- 封口前接受的命令全部执行，封口后消息可靠进入下一 turn。
- 插件反馈、标题、用量和工具注入同样受门控保护。
