# 任务 17：工具流水线收敛

> 需求：[../requirements.md](../requirements.md) §3.4（ALR-301/302）｜设计：[../design.md](../design.md) §8
>
> 状态：**已完成**｜对应方案阶段 7。

## 目标

1. 工具调用整批交给独立流水线：规范化/校验 → 权限判断 → 审批等待 → 有界并行执行 → 顺序提交 → 更新 TaskContract → 闭合 Provider 协议（ALR-301）。
2. 审批是流水线内部的异步等待，与工具共享同一命令通道；Loop 不再拥有 `PreparingTools` / `WaitingTools` / `WaitingApproval` 顶层阶段（ALR-302）。

## 实施结果

### `react/tools.rs`（新增）

- `execute_tool_batch`：准备（校验/去重/权限分流）→ 审批（流水线内等待，`Approval` / `SetTrustMode(→FullTrust)` / 中断三类出口）→ 执行（JoinSet 并行，任务与运行记录一一对应）→ 收尾（无效调用上下文、失败恢复提示、观测压力记录）。
- 命令分流：中断类（取消/关闭/引导消息）到达时批次收敛闭合（运行中任务中止 + 悬空调用闭合 + 协议事件）后交还执行驱动；其余命令（配置更新、工具注入、插件反馈、迟到审批）就地消化不打断执行——与原统一命令处理的 KeepCurrent 类行为一致。
- 审批拒绝保持原语义：记录拒绝结果后，有新注入继续（`NeedModel`）、无新注入以当前内容成功结束（`PendingFinish(Success)`），剩余调用一并闭合。
- 中断时阶段归还：流水线被中断命令打断时先 `install(NeedModel)` 再设 deferred，避免命令处理器 take 阶段时 panic（与任务 16 同类缺陷的预防）。

### execute.rs 接入

- `complete_llm_request` 返回 `NextStep`：`Phase(下一阶段)` 或 `ExecuteTools(批次)`；模型响应含工具调用时由调用方（WaitingModel 完成分支）`await` 流水线，按 `Completed` / `RejectedToFinish` / `Interrupted` 三种结果安装下一阶段。
- 删除主循环的 `PreparingTools` / `WaitingTools` / `WaitingApproval` 三个阶段分支。

### 清理

- `phase.rs`：删三个阶段变体与 `ApprovalPhase` / `PendingApproval` / `ToolExecutionPhase` / `RunningToolCall` / `ToolTaskOutput`（后两者迁入 tools.rs 流水线局部）。
- `command.rs`：审批响应的阶段迁移分支与 `SetTrustMode` 的审批解锁分支删除（均在流水线内处理）；流水线之外的审批一律视为迟到响应明确忽略。
- `interrupt.rs`：`WaitingTools` / `WaitingApproval` 中断分支删除（收敛逻辑迁入流水线的 `abort_running_tools` / `close_pending_calls`）。
