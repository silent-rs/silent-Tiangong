# 任务 16：模型请求策略外置

> 需求：[../requirements.md](../requirements.md) §3.4（ALR-303/304/305）｜设计：[../design.md](../design.md) §9
>
> 状态：**已完成**｜对应方案阶段 6。

## 目标

1. 压缩移出 Loop：不再有 `Compressing` 顶层阶段与分散的压缩续接分支，请求前压力检查与上下文溢出恢复都内联在请求策略中（ALR-303/304）。
2. 压缩统一：三种场景（请求前压力 / 溢出强制 / 手动）共用一份等待与提交逻辑，不再有重复实现。
3. 压缩语义收敛：压缩只是一次摘要调用，产出仅是 session 的一次调整（摘要 + 边界推进）；不再由 LLM 提取"当前任务状态"。

## 实施结果

### `react/request.rs`（新增，请求策略）

- `prepare_before_request`：请求前压力检查（观测信号 = 最近响应/工具批次的 token 总量，跨 turn 经 `session.current_tokens` 持久化）；超阈值先压缩。
- `recover_context_overflow`：上下文溢出错误恢复——强制压缩后重试；边界未推进（无可压缩历史）时明确失败。
- 压缩期间命令双路等待：命令到达即中止压缩并交还执行驱动（归还阶段后设 deferred），取消/steer/关闭均不丢失。

### 压缩统一（`ContextCompression`）

三种压缩合并为一个会话对象：`auto` / `forced` / `manual` 三个构造器 + 单一 `run`（命令策略：`Relay` 上抛主循环 / `ConsumeLocally` 手动场景就地消化）+ 单一 `complete`（按种类计入 turn 累计或 session 并通知）。差异全部由 `CompressionKind` 参数化：分割点、观测用量、用量归属、通知文案。

### 删除对象

- `ExecutionPhase::Compressing`、`CompressionPhase`、`CompressionContinuation`（四个续接分支的路由）。
- Loop 内四处分散压缩点：纯文本响应后、工具批次完成后、无效工具调用后、溢出错误——收敛为请求前 + 溢出恢复两处。
- `interrupt.rs` 的 Compressing 中断分支。
- `[[CURRENT_TASK]]` 机制：压缩提示词的双段落格式、解析、`CompressionUpdate.current_task` 字段、`build_compression_resume_message` 的 LLM 生成续接——压缩输出只有摘要。

### 锚点消息机制（LLM 可见、用户不可见）

压缩分割点保留最近一次完整交互（最新可见消息及其所属工具批次），锚点用户消息**允许被折叠**。锚点被折叠时在摘要边界注入一条合成消息：

- `User` 角色（满足 Provider「首条非 System 消息必须是 User」约束——实测保留区以 assistant/tool 开头会被 provider 开头过滤清空）；
- `MessagePhase::CompressedResume`（前端不展示、搜索或编辑）；
- `ContentBlock::ModelInstruction`（进入模型请求，不属于用户可见文本；provider 层与 Text 同等发送）；
- 内容为被折叠锚点的**原文**，由程序直接复制，不经过 LLM 提取。

### Provider 重试归属确认

Provider 临时错误的退避重试已由模型客户端（`SingleProviderClient::with_on_retry`）承担（实测 400 也会内部重试一次），Loop 不重复该判断；请求策略只处理需要本地动作的溢出与不可恢复错误。修复了一个实施缺陷：请求前压缩被命令打断时阶段所有权未归还，特定取消场景会 panic（`take_phase` 断言）——中断返回前装回 `NeedModel`。

## 测试

- 5 项压缩测试改写为两段式（先以大用量响应建立压力信号，下一 turn 请求前触发压缩），覆盖：摘要与边界持久化、截断拒绝、存储失败保持原状、压缩期间取消（Cancelled 事件）、压缩期间注入（迟到结果不应用）。
- 分割点/锚点断言按新语义更新：保留最近工具批次、锚点消息含用户请求原文、`[[CURRENT_TASK]]` 相关断言删除。
- 手动压缩两项测试不变；压缩单元测试改写（resume 构造测试删除，新增"折叠历史 + 最近交互保留 + 不注入合成任务状态"）。

## 行为变化说明

1. 模型给出最终回复的 turn 结束时不再压缩，推迟到下一 turn 请求前（对当轮无意义，效果等价）。
2. 压缩请求不再生成"当前任务状态"段；当前任务由保留的最近交互或锚点消息（用户原文）承载。
3. 锚点用户消息可被折叠（此前必须保留到锚点处），压缩更彻底。
