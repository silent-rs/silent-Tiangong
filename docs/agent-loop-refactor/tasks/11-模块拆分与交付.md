# 11 - 模块拆分与最终交付

## 目标

在行为和并发模型稳定后进行纯机械模块拆分，清理兼容层，并完成全链路交付检查。

## 范围

- `crates/tiangong-core/src/react/`
- 相关内部导出
- 项目规划、需求和进度文档

## 任务

1. 按 `design.md` 目标目录拆分 phase、command、model、tool、completion、interrupt、ingress。
2. 拆分提交不修改业务逻辑；每次移动后立即验证。
3. 删除兼容适配层、死代码、临时 allow 和过渡注释。
4. 检查外部接口、Session 格式和 StreamEvent 契约是否保持。
5. 运行完整格式、静态检查、核心测试、插件测试和 workspace 编译。
6. 真实验证 GUI/CLI/Server 代表场景：普通问答、工具、审批、压缩、连续引导、取消、Agent Team、封口交接。
7. 更新 PLAN、TODO、requirements、设计和 progress，记录真实提交与验证。
8. 完成交付范围审查；不得混入无关改动。

## 不做

- 不在机械拆分中顺手优化业务。
- 不自动提交、推送或合并。

## 验收

- `execute.rs` 只保留驱动主体，各模块职责清晰。
- 所有 ALR 需求可追踪到实现与测试。
- 完整检查和真实场景验证通过。

## 验证

```bash
cargo fmt -- --check
cargo check --workspace
cargo clippy --workspace --all-targets --tests --benches -- -D warnings
cargo test -p tiangong-core
cargo test -p tiangong-plugin-agent-team
```
