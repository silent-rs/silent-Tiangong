# 00 - 行为基线与重构入口冻结

## 目标

在修改执行核心前，冻结正确行为、已知缺陷、需求追踪、开发基线和回滚点，消除“行为不变”和“修复当前缺陷”的冲突。

## 范围

- `docs/agent-loop-refactor/`
- `PLAN.md` / `TODO.md`
- 只读核对当前实现与测试

## 任务

1. 逐项确认 `requirements.md` 的行为基线表和 ALR 需求。
2. 明确以下已知问题是否纳入重构：PendingFinish 工具注入、晚到用量、终态封口竞态。
3. 确认开发基线：先合并引导消息分支并同步最新主线，再创建 `feature/agent-execution-core`。
4. 记录绿色基线提交、测试数量和验证输出。
5. 建立每个后续任务独立提交、独立审查、失败回滚到上个绿色提交的规则。

## 不做

- 不修改生产代码。
- 不增加实现性测试。

## 验收

- 行为基线、已知缺陷、本轮修复范围均无“待开发者自行决定”项。
- PLAN/TODO 与本目录一致。
- 进度文档记录真实基线、分支和验证。

git status --short --branch
git log -1 --oneline
