# 10 - 完成度策略简化评估

## 目标

在状态机和终态门控稳定后，将 Summary/ForceFinal 解耦为可替换完成度策略，并用数据决定是否减少独立 Summary 请求。

## 范围

- `react/completion.rs`
- 完成度相关提示与测试
- 性能、用量和完成质量指标

## 任务

1. 定义 `CompletionPolicy` 与 `CompletionAction`，先适配现有 Summary/ForceFinal 行为。
2. 记录直接回答、工具后回答、NeedMoreWork、AskUser、ForceFinal 的触发与结果指标。
3. 实现可配置的按需 Summary 实验策略：明显完整答复可直接 PendingFinish，其余保留检查。
4. 建立同一代表性场景的质量、延迟、模型请求数和 token 对照。
5. 只有指标达到约定阈值才切换默认策略；保留回滚开关。
6. 若收益不足，保持现有策略并仅保留架构解耦。

## 不做

- 不在没有对照数据时直接移除 Summary。
- 不与状态机迁移混在同一提交。

## 验收

- 完成度策略与执行驱动解耦。
- 默认行为变化有自动化测试、数据依据和回滚路径。
- 用户任务完成率不因减少请求而明显下降。
