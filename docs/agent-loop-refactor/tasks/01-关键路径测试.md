# 01 - 关键路径与不变量测试

## 目标

在核心重构前，用自动化测试冻结阶段迁移、命令顺序、生命周期、事件顺序、消息锚点、工具协议和用量语义。

## 范围

- `crates/tiangong-core/src/react/` 测试
- 必要的 core 集成测试
- 测试辅助结构；不改生产行为

## 任务

1. 建立阶段 × 命令代表矩阵：WaitingModel、WaitingTools、WaitingApproval、Compressing、CheckingCompletion、PendingFinish。
2. 覆盖用户引导、Cancel、InjectTool、ReportUsage 四类关键命令。
3. 覆盖连续命令顺序：多条用户消息、配置更新、最终 Cancel。
4. 覆盖 Summary 中断降级、NeedMoreWork、ForceFinal、压缩续接。
5. 覆盖最新用户消息状态锚点和磁盘重载一致性。
6. 覆盖一次物理 turn 的生命周期与唯一终态。
7. 覆盖工具调用中断后的协议闭合。
8. 覆盖引导不触发插件 `on_cancel`、显式取消触发一次。
9. 记录关键流事件序列，保护外部事件契约。
10. 对已知缺陷写目标行为测试；若无法在生产修复前通过，使用明确的 ignored/待修复标记并绑定后续任务，不允许假装绿色。

## 不做

- 不追求无关模块 100% 覆盖。
- 不以手工验证替代核心迁移测试。

## 验收

- 每项 ALR 行为需求至少有一个自动化验证落点。
- 测试名称直接表达业务行为和失败原因。
- 后续任务可用同一测试集判断行为回归。

## 验证

```bash
cargo fmt -- --check
cargo clippy -p tiangong-core --all-targets --tests --benches -- -D warnings
cargo test -p tiangong-core
```
