# 02 - 阶段驱动原型与所有权验证

## 目标

先用最小原型验证单阶段状态机在 Rust 中的所有权、`tokio::select!`、取消和阶段迁移实现方式，避免在主循环迁移中临时设计。

## 范围

- 独立测试模块或 `react/phase.rs` 的最小内部原型
- 不接入生产 `execute_turn`

## 任务

1. 实现“取出阶段 → 等待一个事件 → 安装新阶段”的最小驱动原型。
2. 验证阶段持有 `JoinHandle`、`JoinSet`、receiver 和批次数据时可安全迁移。
3. 验证命令分支可在不重新引入并列活动 `Option` 的情况下替换阶段。
4. 定义迁移失败和 panic 时的诊断策略，避免静默“无阶段”。
5. 明确 Ready 阶段与 Waiting 阶段驱动方式，不引入含义模糊的 `is_idle`。
6. 形成一份简短设计决策，写回 `design.md`；原型代码如无生产价值可在任务结束时删除。

## 不做

- 不迁移真实模型、工具、压缩业务。
- 不改变现有控制流。

## 验收

- 主状态机的 Rust 实现骨架已有可编译、可测试结论。
- 后续任务无需自行选择另一套所有权模型。
- 不产生长期并存的第二套未使用状态机。
