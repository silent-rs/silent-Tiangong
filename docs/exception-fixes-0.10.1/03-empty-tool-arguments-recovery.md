# 03 - 工具空参数/解析失败恢复增强

## 目标

减少并修复 Agent 在调用 `read_file`、`run_shell`、`run_command`、`multi_tool_use.parallel` 等工具时出现空参数或非法参数后反复失败的问题。

## 范围

- `crates/tiangong-core/src/react/engine.rs` 中工具调用失败处理链路
- `crates/tiangong-core/src/react/message.rs` 中工具结果写入和运行时消息写入
- LLM Provider 工具调用参数解析相关代码，尤其 OpenAI Chat Completions 流式工具参数聚合
- 工具描述或 system prompt 中的工具调用约束
- `multi_tool_use.parallel` 的错误隔离行为，如该工具由当前项目实现或可配置

## 依赖

- 前置任务：01
- 后续任务：04、06
- 可并行任务：02
- 阻塞说明：如果 01 未完成，无法确认本修复是否进入 0.10.1 异常修复范围。

## 任务

- 梳理空参数失败的来源：模型输出、Provider 参数聚合、工具 schema 校验、并行工具包装层。
- 对空参数/非法参数建立明确错误类型，不只作为普通文本错误。
- 避免同一轮重复调用相同工具和相同空参数。
- 确保失败恢复提示不会诱导模型把 `__parse_error` 当成真实工具参数。
- 强化工具调用规范：工具参数必须是完整 JSON；不确定参数时先重新规划或询问用户。
- 对并行工具调用中的单个失败进行隔离，保留其他成功工具结果。
- 增加回归测试或构造最小模拟用例。

## 不做

- 不改变工具本身的业务能力。
- 不重构整个 ReAct 主循环。
- 不实现只读工具并行调度。
- 不改变权限审核策略。

## 验收

- 空参数工具调用失败后，下一步不会继续重复同一工具同一空参数。
- 错误信息清晰提示模型重新生成完整 JSON 参数。
- 并行工具组中一个工具参数错误时，其他有效工具结果仍可使用。
- 对 `__parse_error` 的处理只作为运行时错误反馈，不会被再次作为真实参数传入。
- 有测试或日志能覆盖空参数失败恢复场景。

## 验证

- `cargo fmt -- --check`
- `cargo check --workspace`
- 运行 Provider 工具调用解析相关测试。
- 手动构造空参数工具调用，确认失败恢复行为符合预期。
