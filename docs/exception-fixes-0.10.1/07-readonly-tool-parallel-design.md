# 07 - 只读工具并行执行设计

## 目标

设计安全的只读工具并行执行策略，为后续提升 Agent 复杂任务执行效率做准备。

## 范围

- 工具元数据分类
- 工具执行调度策略设计
- ReAct 工具执行阶段设计
- 权限审核与并行执行关系
- 失败隔离与结果排序规则
- 后续实现任务拆分

## 依赖

- 前置任务：04、06
- 后续任务：无
- 可并行任务：无
- 阻塞说明：04 未完成前，工具执行阶段没有清晰边界；06 未完成前，并行失败隔离缺少结构化基础。

## 任务

- 定义工具副作用分类：
  - 只读工具
  - 文件写入工具
  - 命令执行工具
  - 浏览器交互工具
  - 数据库写入工具
  - Agent 团队管理工具
  - 调度器变更工具
- 明确哪些工具允许并行，哪些必须串行。
- 明确权限审核发生在并行调度前还是调度中。
- 设计并行结果排序：保持模型 tool_call 顺序写回，还是按完成时间写回。
- 设计并行失败隔离：一个工具失败不能取消其他安全工具，除非属于同组强依赖。
- 设计并发上限和 token/输出预算。
- 拆分后续实现任务 spec。

## 不做

- 本任务只做设计，不实现并行执行。
- 不改变当前工具串行行为。
- 不修改工具 schema。
- 不引入新的异步运行时。

## 验收

- 有明确工具分类表。
- 有并行/串行决策规则。
- 有权限审核和失败隔离设计。
- 有后续实现任务拆分。
- 设计能说明为什么浏览器点击、文件写入和 shell 命令默认不并行。

## 验证

- 手动审查设计文档。
- 如仅文档变更，可不运行编译命令。
