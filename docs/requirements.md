# 天工需求整理

## 文档目的
用于对齐天工当前阶段（Phase 1）的功能边界与交付范围，作为 RFC 与 TODO 的执行基线。

## 当前范围（Phase 1）

### Must
- 单 Agent 对话能力可用。
- 桌面端提供对话、会话切换、执行状态展示。
- 桌面端提供独立配置窗口，用于模型供应商参数配置（基于多窗口能力）。
- 主界面需要提供固定可见的配置打开入口，确保用户可直接打开模型供应商配置窗口。
- 模型供应商配置字段统一使用 `API_AUTH_TOKEN`、`API_BASE_URL`、`API_TIMEOUT_MS`、`API_MODEL`（不使用供应商前缀字段名）。
  - 直接替换旧 `provider/model` 配置模式，当前阶段不做兼容读取。
  - 配置结构参考：
    ```json
    {
      "API_AUTH_TOKEN": "*****************",
      "API_BASE_URL": "https://api.openai.com/v1",
      "API_TIMEOUT_MS": "3000000",
      "API_MODEL": "gpt-4o-mini"
    }
    ```
- 建立最小执行链路：输入 -> 规划 -> 执行 -> 输出。
- 提供单一远程模型供应商接入抽象（先单实现）。
- 模型调用必须真实发起远程 HTTP 请求（非本地 mock 返回）。
- 模型调用实现统一使用 OpenAI SDK（兼容 OpenAI 协议的供应商网关）。
- 在保留 OpenAI SDK 网关模式的同时，需支持天工自身的本地 CLI 交互模式（终端 REPL 对话入口）。
- 提供最小工具调用协议抽象（可先最小实现）。
- 提供最小内置工具能力并接入运行链路：`read_file`、`list_dir`、`run_command`（受限命令）。
- 工具执行结果需结构化返回（`summary/stdout/stderr/exit_code`），用于主界面状态展示与后续审计。
- 会话数据支持本地持久化与恢复。
- 本地存储结构需拆分为应用配置与会话数据两层：
  - 应用配置写入 `.tiangong/app.json`。
  - 对话会话写入 `.tiangong/sessions/` 目录，单会话单文件。
  - 会话文件名必须使用 `scru128`（如 `<scru128>.json`）。

### Should
- 支持上下文裁剪，避免对话上下文无限增长。
- 提供统一运行状态机（Idle/Planning/Executing/Completed/Failed）。
- 提供最小审计字段（时间、会话、任务、耗时、结果）。
- 模型供应商配置修改后支持本地持久化，并在当前运行实例中即时生效。
- 模型供应商配置支持 JSON 友好结构存储，配置键名与 UI 字段名保持一致。
- 设置页支持基于当前配置调用模型网关获取可用模型列表，并将结果用于 `API_MODEL` 选择。
- 设置页获取的模型列表需要持久化到本地配置文件，应用重启后可恢复并继续用于模型选择。
- 主界面对话发送区需提供模型选择控件，且与 `API_MODEL` 同步，切换后即时生效并持久化。
- 主界面需支持会话重命名与会话删除，并在本地存储中保持一致。
- 模型响应需支持流式与非流式两种模式，主界面状态区可展示流式输出信息（模式、分片数量）。
- 流式模式下主界面必须增量展示模型输出内容，请求进行中不得阻塞输入、会话切换、窗口交互等 UI 操作。
- 会话切换与模型选择等轻量操作不得触发全量会话落盘，需采用增量持久化策略（仅更新必要文件）。
- 对话发送链路需降低落盘频率：单轮请求开始时仅更新内存状态，待本轮完成或失败后再批量持久化。
- 主界面视觉风格应向 ChatGPT/Claude 的桌面聊天界面靠拢：深色侧栏、清晰顶部栏、消息气泡与底部输入区分层明确。
- 主界面对话区布局需基于 flex 弹性模型：消息列表可滚动、输入区固定可见，窗口缩放时内容不得被裁剪或横向溢出。
- 主界面对话呈现需对齐 ChatGPT Desktop 风格：正文区域不使用消息气泡背景；对话流需展示用户与助手消息，用户消息采用右侧对齐的轻量样式。
- 对话文本必须支持自动换行（含长单词/长 URL/连续字符），不得出现横向溢出或内容被裁剪。
- 主界面 UI 结构需组件化：左侧会话列表与右侧对话内容区作为独立组件实现，主页面仅负责状态组装与布局拼接。
- 主界面用户输入区（模型选择、输入框、发送按钮）需独立为组件，便于复用与后续交互扩展。
- 需提供 `tiangong chat` 终端交互命令，支持连续多轮对话、上下文保留、退出控制（如 `/exit`）。

### 非目标（Phase 1 不做）
- 多模型供应商并行路由。
- 分布式调度。
- 全量插件生态。
