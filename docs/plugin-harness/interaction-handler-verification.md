# interaction-handler 插件开发验证清单

> 插件工程：`plugins/interaction-handler`（Vue 3 + Vite，默认交互处理器）
> 关联设计：`./interaction-model-redesign.md`；开发流程：`../plugin-development.md` 开发流程总览
> 状态：代码与自动化测试已通过，**GUI 手动验证待执行**（本文即验证脚本）

## 前置准备

```bash
cd plugins/interaction-handler
yarn install          # 首次
yarn package          # 构建并组装 release/（插件包）
```

导入：天工「设置 → 插件管理 → 导入本地插件」→ 选择 `release/` 目录。

**导入校验点**：

- [ ] 导入成功，插件列表出现「交互处理器」（interaction-handler），状态已加载
- [ ] 清单解析通过（若失败，日志现在会给出具体字段原因——曾有旧包含 `host_handler` 被拒的案例，重新 `yarn package` 导入即可）
- [ ] 卸载后重新导入可正常（当前版本 0.3.0）

## 工具注册验证（声明式 TS 工具）

模型侧应能看到 `request_user` 工具（来自插件 manifest 的 `tools[]` 声明，
经 TsPluginAdapter 注入；卸载插件后工具应消失）。

- [ ] 新会话提问：「你现在可以使用哪些工具？」——回答中应包含 request_user
- [ ] （可选）卸载插件后再问——request_user 不在列表

## 六种交互逐项验证

每种交互验证三点：**模型正确发起**（工具调用参数合法）、**插件界面正常**
（interaction 卡片覆盖输入区，倒计时走动）、**响应回传生效**（工具结果
携带用户选择，模型据此继续）。

- [ ] 卡片显示期间输入区被完全遮住，键盘、鼠标、拖放和语音快捷操作均不可用
- [ ] 交互卡片是会话区域的独立 Shadow 弹层，不嵌在输入组件内；普通第三方 Shadow 处理器也可动态加载
- [ ] 普通长度的标题、说明、问题和操作按钮一次完整显示，不出现整页滚动条
- [ ] 超长文本、大量选项或较长表单只滚动中间内容区，顶部状态、关闭按钮和底部操作按钮始终可见
- [ ] 切换会话后插件实例不重建，返回原会话时仍能看到其未结束请求
- [ ] 所有交互类型均显示关闭按钮
- [ ] 点击关闭按钮后工具结果为 cancelled，并向模型返回“用户关闭了相关操作”

### 1. approval（审批）

提问：「删除 /tmp/interaction-test.txt 前先征求我是否同意」。

- [ ] 审批与普通征询都通过同一 `request_user` 通道进入同一个插件界面
- [ ] 卡片显示两个按钮：同意 / 拒绝
- [ ] 点「同意」→ 用户意见返回模型，由模型决定是否继续
- [ ] 再触发一次同类审批 → 点「拒绝」→ 模型不再执行并解释

### 2. confirm（确认）

提问：「删除前先问我要不要继续」（或让模型在流程中确认）。

- [ ] 卡片显示「是 / 否」按钮
- [ ] 点「是」→ 模型收到 true 继续执行；点「否」→ 模型收到 false 停止

### 3. choice（单选）

提问：「问我用哪个分支：main 还是 dev，然后告诉我你的选择」。

- [ ] 卡片显示两个选项（单选高亮）
- [ ] 选择后提交 → 模型复述所选分支

### 4. multi_choice（多选）

提问：「让我从 [' Alpha', 'beta', 'gamma'] 里多选几项，然后把选择列出来」。

- [ ] 卡片选项可多选（勾选态）
- [ ] 提交后模型列出全部所选

### 5. input（文本输入）

提问：「问我的邮箱是多少，然后复述给我」。

- [ ] 卡片显示文本框
- [ ] 输入后提交 → 模型复述输入内容

### 6. form（表单）

提问：「让我填一个表单：姓名、数量、是否启用，然后总结」。

- [ ] 卡片显示对应字段（文本/数字/勾选框）
- [ ] 提交后模型按字段值总结

## 超时与竞态验证

- [ ] 弹出交互后**不做任何操作**，等待 15 秒 → 卡片自动变为已过期，
      工具结果为 expired，模型说明用户未响应并自行决策（放弃/重问）
- [ ] 倒计时显示与插件独立计算的 15 秒时限基本一致
- [ ] 提交后按钮进入提交中状态，不可重复点击
- [ ] （竞态）在第 15 秒边缘点击提交 → 只有一个结果生效（answered 或
      expired，不出现双结果）

## 中断验证

- [ ] 弹出交互后无法通过底层输入框发送新消息
- [ ] 点击关闭按钮后交互被取消（cancelled），悬空工具调用被正确闭合
- [ ] 插件界面收到关闭事件后禁用输入（迟到提交被拒绝）

## 多界面/无处理器场景（如已实现）

- [ ] 内置界面与插件界面不并存（插件接管后内置卡片不出现）
- [ ] 禁用（不停卸）插件后发起交互 → 按 CLI/降级路径或安全超时处理

## 已知边界（当前实现）

1. CLI 入口的交互处理已随「交互移出 Core」重构移除，终端下 request_user
   依赖 TS 插件机制（桌面）——CLI 场景待补终端宿主。
2. 审批挑战/授权体系随重构删除；审批与普通征询使用同一插件通道，插件只收集用户意见，Agent 自行决定后续步骤。
3. `session.write` 等新权限与 `tool.provide` 已在桥接白名单，第三方处理器
   需声明对应权限。
