> 关联设计：`./interaction-model-redesign.md`；开发流程：`../plugin-development.md` 开发流程总览

## 前置准备

```bash
cd plugins/interaction-handler
yarn install          # 首次
yarn package          # 构建并组装 release/（插件包）
```

导入：天工「设置 → 插件管理 → 导入本地插件」→ 选择 `release/` 目录。

**导入校验点**：

- [ ] 导入成功，插件列表出现「交互处理器」（interaction-handler），状态已加载
- [ ] 清单解析通过（若失败，日志现在会给出具体字段原因——曾有旧包含 `host_handler` 被拒的案例，重新 `yarn package` 导入即可）
- [ ] 卸载后重新导入可正常（同版本 0.1.0 允许重导入）

## 工具注册验证（声明式 TS 工具）

模型侧应能看到 `request_user` 工具（来自插件 manifest 的 `tools[]` 声明，
经 TsPluginAdapter 注入；卸载插件后工具应消失）。

- [ ] 新会话提问：「你现在可以使用哪些工具？」——回答中应包含 request_user
- [ ] （可选）卸载插件后再问——request_user 不在列表

## 六种交互逐项验证

每种交互验证三点：**模型正确发起**（工具调用参数合法）、**插件界面正常**
（interaction 卡片出现在消息区，倒计时走动）、**响应回传生效**（工具结果
携带用户选择，模型据此继续）。

### 1. approval（审批）

提问：「帮我删除 /tmp/interaction-test.txt 这个文件」（Supervised 模式下
工具会返回 approval_required 挑战，模型应发起 approval 请求）。

- [ ] 卡片显示三个按钮：仅本次允许 / 本次运行内允许 / 拒绝
- [ ] 点「仅本次允许」→ 工具执行完成，模型继续（文件被删或工具成功执行）
- [ ] 再触发一次同类审批 → 点「拒绝」→ 模型不再执行并解释
- [ ] 点「本次运行内允许」→ 同会话再次触发同类操作**不再弹窗**，直接执行
- [ ] 重启应用 → 运行期授权失效，审批重新弹出

### 2. confirm（确认）

提问：「删除前先问我要不要继续」（或让模型在流程中确认）。

- [ ] 卡片显示「是 / 否」按钮
- [ ] 点「是」→ 模型收到 true 继续执行；点「否」→ 模型收到 false 停止

### 3. choice（单选）

提问：「问我用哪个分支：main 还是 dev，然后告诉我你的选择」。

- [ ] 卡片显示两个选项（单选高亮）
- [ ] 选择后提交 → 模型复述所选分支

### 4. multi_choice（多选）

提问：「让我从 [' Alpha', 'beta', 'gamma'] 里多选几项，然后把选择列出来」。

- [ ] 卡片选项可多选（勾选态）
- [ ] 提交后模型列出全部所选

### 5. input（文本输入）

提问：「问我的邮箱是多少，然后复述给我」。

- [ ] 卡片显示文本框
- [ ] 输入后提交 → 模型复述输入内容

### 6. form（表单）

提问：「让我填一个表单：姓名、数量、是否启用，然后总结」。

- [ ] 卡片显示对应字段（文本/数字/勾选框）
- [ ] 提交后模型按字段值总结

## 超时与竞态验证

- [ ] 弹出交互后**不做任何操作**，等待 15 秒 → 卡片自动变为已过期，
      工具结果为 expired，模型说明用户未响应并自行决策（放弃/重问）
- [ ] 倒计时显示与 15 秒基本一致（宿主权威 deadline）
- [ ] 提交后按钮进入提交中状态，不可重复点击
- [ ] （竞态）在第 15 秒边缘点击提交 → 只有一个结果生效（answered 或
      expired，不出现双结果）

## 中断验证

- [ ] 弹出交互后直接发送一条新消息 → 交互被取消（cancelled），模型按
      新消息继续，悬空工具调用被正确闭合
- [ ] 插件界面收到关闭事件后禁用输入（迟到提交被拒绝）

## 多界面/无处理器场景（如已实现）

- [ ] 内置界面与插件界面不并存（插件接管后内置卡片不出现）
- [ ] 禁用（不停卸）插件后发起交互 → 按 CLI/降级路径或安全超时处理

## 已知边界（当前实现）

1. CLI 入口的交互处理已随「交互移出 Core」重构移除，终端下 request_user
   依赖 TS 插件机制（桌面）——CLI 场景待补终端宿主。
2. 审批挑战/授权体系随重构删除：Supervised 下不再有 Core 层强制拦截，
   受保护工具的强制审批层待按新模型重新设计（插件 TS 逻辑自行判断）。
3. `session.write` 等新权限与 `tool.provide` 已在桥接白名单，第三方处理器
   需声明对应权限。
