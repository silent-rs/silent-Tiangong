# T003 - Host Bridge 后端命令层

## 目标

打通插件 UI 与宿主之间的统一桥接通道：新增后端命令支持 `bridge.call`（调用宿主能力）与 `bridge.on`（订阅宿主事件），并按权限命名空间做白名单校验。它是 UI 沙箱与逻辑运行时、内置服务之间的唯一通信管道。

## 范围

- 后端：`src-tauri/src/commands.rs` 新增桥接命令（如 `bridge_call`、`bridge_subscribe`），或经 `tiangong-plugin-runtime` 暴露桥接接口。
- 权限：`permissions` 中 `bridge.call`、`bridge.events` 等命名空间的校验逻辑。

## 依赖

- 前置任务：T001（类型与 Seam Hub 定型）。
- 后续任务：T004（设置页容器调用桥接）、T006（沙箱容器）、T014（审批）、T015（交互）。
- 可并行任务：T002（Manifest 解析）。
- 阻塞说明：桥接命令需要 T001 定义的桥接能力命名空间与白名单结构。

## 任务

- [ ] 定义桥接能力命名空间（`plugin.*`/`session.*`/`tool.*`/`approval.*`/`interaction.*`/`storage.*`）与权限映射。
- [ ] 实现 `bridge.call(method, payload)`：鉴权 → 白名单校验 → 路由到 WASM 逻辑层或内置服务 → 返回序列化结果。
- [ ] 实现 `bridge.on(channel)` 的订阅通道骨架：按 `capabilities.events` 命名空间放行，未知 channel 拒绝。
- [ ] 未知 method 拒绝并记录；透传负载不解析业务 JSON（保持宿主中性）。
- [ ] 前端 `api/tauri.ts` 封装 `bridgeCall`/`bridgeOn`。

## 不做

- 不实现具体 UI 容器的渲染（T004/T006）。
- 不实现审批/交互的实际路由逻辑（T014/T015）。
- 不实现事件流的完整推送（事件源接入在 T007 之后按需补）。

## 验收

- `bridge.call` 能经白名单调用一个最小宿主能力（如 `plugin.*` 转发到 WASM `handle-view-message`）并返回结果。
- 未知 method 被拒绝并记录日志。
- 权限命名空间与 `capabilities.events` 的放行/拒绝行为正确。

## 验证

- `cargo check`（后端）+ `yarn --cwd frontend build`（前端类型）。
- 补充桥接命令单元测试：白名单内通过、白名单外拒绝、权限缺失拒绝。
- 用现有 Memory 插件的 `handle-view-message` 走一次 `bridge.call` 冒烟验证。
