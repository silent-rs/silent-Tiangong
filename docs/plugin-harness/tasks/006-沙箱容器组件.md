# T006 - Shadow/iframe 沙箱容器组件

## 目标

实现标准 Slot 容器（`<TgSlot>` 语义）：按 UI 贡献声明的 `sandbox` 级别选择渲染方式——`shadow`（默认，挂载主 DOM 树）或 `iframe`（强隔离，等价现有 srcdoc 模式），两种容器对插件暴露统一的宿主桥接与主题 token。

## 范围

- 前端：`frontend/src/components/PluginSandbox.tsx`（新增通用沙箱容器），复用 T003 的 `bridgeCall` 与 T004 的主题 token 注入。
- 接入点：`settings.plugin-page` 的 v2 manifest 贡献经新容器渲染（v1 WASM 贡献维持现有 iframe 通道不变）。

## 依赖

- 前置任务：T003（桥接命令）、T004（iframe 容器与 token 注入）。
- 后续任务：T007（extension.tab 挂载复用本容器）。
- 可并行任务：无。

## 任务

- [ ] 通用容器组件 `PluginSandbox`：输入 `{ pluginId, contributionId, sandbox, html, title }`，`sandbox: "shadow"` 走 Shadow DOM 渲染，`"iframe"` 复用现有 `PluginIframe`。
- [ ] Shadow 容器：宿主元素 `attachShadow({ mode: "open" })`，入口 HTML 注入 shadow root；HTML 内 `<script>` 以受控方式提取执行（不随 innerHTML 静默丢失）；宿主主题 token 以 CSS 变量注入 `:host`，随主题切换刷新。
- [ ] 桥接注入：shadow 容器内插件脚本经 `window.__tiangong_bridge.call(method, payload)` 走 T003 桥接（等价 iframe 的 postMessage 通道），负载透传不做业务解析。
- [ ] 卸载清理：容器卸载时断开 shadow root 脚本的全局监听，不残留状态（贡献可逆）。
- [ ] v2 manifest 贡献接入：`PluginSettingsPanel`/`PluginView` 中 `sandbox === "shadow"` 的贡献走新容器。

## 不做

- native 容器（M2 官方插件迁移时实现）。
- `extension.tab`、会话区 Slot 的挂载位置与实例管理（T007 起）。
- Shadow 容器的 CSP、window/document 完整代理等深度 JS 沙箱（受限执行环境随安全需求迭代，当前以桥接白名单为界）。
- v2 示例插件制品（T016 SDK/脚手架一并交付）。

## 验收

- `sandbox: "shadow"` 与 `"iframe"` 两种贡献分别经对应容器渲染出页面。
- shadow 容器内脚本可经注入的 bridge 完成一次 `plugin.*` 调用并拿到结果。
- 主题切换时 shadow 容器的 CSS 变量与 iframe 的 hostContext 同步刷新。
- v1 插件设置页行为与 M0 完全一致（回归）。

## 验证

- `yarn --cwd frontend build` 与 `yarn --cwd frontend test` 通过。
- 新增组件测试（vitest + jsdom）：shadow 挂载、脚本执行、bridge 转发、卸载清理、token 注入。
- 构造 v2 测试贡献（sandbox=shadow/iframe）手动冒烟 settings.plugin-page 渲染。
