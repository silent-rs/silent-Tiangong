# T021/T022 - 终端、浏览器插件转化（参考 interaction-handler 模式）

> 分支：`feature/terminal-browser-pluginization`（自 `feature/plugin-harness` 迁出）
> 参考实现：`plugins/interaction-handler`（纯 TS 工具插件 + 宿主服务桥接）
> 目标：终端、浏览器从「编译进 App 的原生插件」转为 manifest v2 插件工程——
> 声明归插件（工具/prompt/UI Slot），原生能力（PTY/webview）经宿主服务桥接。

## 实现模式（与 interaction-handler 同构）

```
plugins/terminal-handler/            新插件工程（Vue/TS）
├── plugin.json                      manifest v2：tools[] + prompt[] + ui.contributions
├── src/                             TS 壳：tool.requested → bridge.call("terminal.*") → tool.resolve
└── （yarn package → release/ 导入）

宿主桥接：set_terminal_handler / set_browser_handler（桌面入口注入，
  复用 crates/plugins/tiangong-plugin-{terminal,browser} 的原生实现）
UI：extension.tab Slot；官方 native 容器（PTY xterm / webview）保留原生渲染
```

与交互插件的差异：PTY/webview 无法在插件沙箱执行，故工具执行是
「插件 TS 壳（策略/转发）→ 宿主桥接服务（原生能力）」两级；声明与
路由仍全部在插件清单。

## 任务拆分

- T021a 桥接服务通道：`terminal.*` / `browser.*` 方法白名单与权限
  （`terminal.use` / `browser.use`），`set_terminal_handler` /
  `set_browser_handler` 注入接口（对齐 `set_session_input_handler` 模式）。
- T021b 终端插件工程：`plugins/terminal-handler`——工具声明
  （terminal_run/send/read 等对齐现有 tools）、TS 壳转发、extension.tab UI、
  prompt 段落、yarn package 打包。
- T021c 宿主接线：main.rs 注入 handler（复用 session_pty/manager）、
  前端 TerminalTabContent 改为该插件 native 容器、官方 App 目录指向新插件。
- T022a-c 浏览器同理（webview manager 复用）。
- T023 验证：卸载插件后工具消失；工具执行经全链路；UI 正常；agent 使用
  浏览器/终端的既有行为回归。

## 边界

- 原生渲染组件（xterm/webview 容器）保留在宿主（native 容器语义），
  转化的是**声明、工具路由、管理 UI 与生命周期归属**。
- 旧 `plugin:terminal|*` / `plugin:browser|*` 命令保留至验证通过后移除。
