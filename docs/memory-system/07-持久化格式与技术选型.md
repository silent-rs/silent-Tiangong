# 07 - 持久化格式与技术选型

## 设计决策

### 主存储：JSON 文件

**选择理由**：
- 与天工现有存储一致（`app.json`, `sessions/`）
- 人类可读，可手动编辑和调试
- 无外部依赖
- 对单用户桌面应用足够

**适用范围**：Profile、Workspace、Episode、Entity、Decision、Evidence、Injection

### 索引：内存索引 + JSON 持久化

**选择理由**：
- MemoryNode 索引体积小（每条约 200 字节），1000 条约 200KB
- 启动时全量加载到内存，搜索延迟 < 1ms
- 避免引入 SQLite 依赖

```rust
/// 索引文件路径
/// ~/.tiangong/memory/workspaces/<workspace_id>/index.json
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct MemoryIndex {
    pub version: u32,
    pub updated_at: String,
    pub nodes: Vec<MemoryNode>,
}
```

### 向量搜索：Phase D 再引入

**现阶段不引入的理由**：
- Episode 数量预计 < 200 条时，关键词匹配足够
- 避免引入 embedding 模型依赖和向量数据库
- 降低初期复杂度

**Phase D 候选方案**：
| 方案 | 优点 | 缺点 |
|------|------|------|
| `usearch` (Rust) | 纯 Rust，无外部依赖 | 功能较简单 |
| `qdrant` 嵌入式 | 功能完整 | 依赖较重 |
| 自建简易向量索引 | 完全可控 | 需要自行实现 |

推荐 Phase D 使用 `usearch`，因其纯 Rust + 零依赖特性与天工技术栈匹配。

## 数据完整性

### 写入安全

采用"写临时文件 + 原子重命名"策略，防止写入中断导致文件损坏：

```rust
fn atomic_write(path: &Path, content: &[u8]) -> Result<()> {
    let tmp = path.with_extension("tmp");
    fs::write(&tmp, content)?;
    fs::rename(&tmp, path)?;
    Ok(())
}
```

### 索引一致性

索引与详细文件保持最终一致：
- 写入 Episode/Entity/Decision 时，同步更新 index.json
- 如果索引损坏，可从 episodes/entities/decisions 目录重建
- 提供 `rebuild_index()` 恢复函数

```rust
pub fn rebuild_index(workspace_id: &str) -> Result<MemoryIndex> {
    let mut nodes = Vec::new();
    // 扫描 episodes/ 目录
    for entry in fs::read_dir(episodes_dir)? {
        let episode: Episode = serde_json::from_str(&fs::read_to_string(entry?.path())?)?;
        nodes.push(MemoryNode::from_episode(&episode));
    }
    // 扫描 entities/ 和 decisions/ 同理
    Ok(MemoryIndex { version: 1, updated_at: now_text(), nodes })
}
```
