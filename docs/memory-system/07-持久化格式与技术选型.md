# 07 - 持久化格式与技术选型

## 设计决策：三层存储架构

天工 Memory 采用"**元数据库 + 全文检索 + 向量语义检索**"三层存储架构，而非纯 JSON 文件方案。

### 总览

| 层次 | 引擎 | 职责 | 数据范围 |
|------|------|------|---------|
| 元数据层 | SQLite（加密） | 记忆管理、索引、元数据、生命周期 | 所有 MemoryNode 及其元数据 |
| 全文检索层 | Tantivy | 精确关键词/短语/BM25 召回 | 摘要、标题、标签、代码符号、路径、错误文本 |
| 向量语义层 | Qdrant | 语义相似度召回、跨表达方式匹配 | Episode/Decision/Entity 的 embedding |
| Injection 层 | Markdown 文件 | 人类可读的注入内容 | Profile/Workspace/Session agent.md |

> **降级策略**：向量语义层为可选组件。当 `LlmConfig.embedding` 未配置时，Qdrant 引擎不初始化，向量语义检索和存储自动跳过，Memory 系统降级为“SQLite + Tantivy”双层架构，仅依赖全文检索召回。

### 为什么不只用 JSON 文件

| 方案 | 优点 | 缺点 |
|------|------|------|
| 纯 JSON 文件 | 简单、无依赖 | 记忆条目增多后检索慢、无全文搜索、无语义匹配 |
| JSON + 内存索引 | 启动快 | 重启丢失索引、多进程不一致、无法搜索正文 |
| **SQLite + Tantivy + Qdrant** | 结构化管理 + 精确检索 + 语义召回 | 引入外部依赖 |

随着 Episode 积累到数百条以上，简单的关键词 `contains` 匹配既不准确也不高效。双引擎架构从一开始就为检索质量打好基础。

## 元数据层：SQLite（加密存储）

### 选型理由

- 嵌入式数据库，零部署成本
- 事务支持，写入原子性保证
- 多进程安全（WAL 模式）
- 与 Actor 模型配合良好：Actor 独占 DB 连接

### 加密方案

使用 `rusqlite` + `sqlcipher` 特性，数据库文件加密存储。密钥基于用户 home 目录绝对路径生成，确保：
- 同一用户在同一机器上可正常访问
- 数据库文件被拷贝到其他用户/机器时无法打开

```rust
use sha2::{Sha256, Digest};

/// 生成 SQLite 加密密码
/// 基于用户 home 目录绝对路径的 SHA-256 hash
pub fn derive_db_password() -> String {
    let home = dirs::home_dir().expect("无法获取用户 home 目录");
    let abs_path = home.canonicalize().unwrap_or(home);
    let digest = Sha256::digest(abs_path.to_string_lossy().as_bytes());
    hex::encode(digest)
}

/// 打开加密数据库
pub fn open_encrypted_db(db_path: &Path) -> Result<rusqlite::Connection> {
    let conn = rusqlite::Connection::open(db_path)?;
    let password = derive_db_password();
    conn.pragma_update(None, "key", &password)?;
    conn.pragma_update(None, "journal_mode", "WAL")?;
    Ok(conn)
}
```

## 全文检索层：Tantivy

### 选型理由

- **纯 Rust**，与天工技术栈完美匹配
- 嵌入式，无外部进程依赖
- BM25 评分，支持布尔查询、短语匹配、模糊搜索
- 延迟低（< 5ms），适合做即时召回

### 适用内容

凡是"用户可能原样搜出来"的内容都应进入 Tantivy：

| 字段 | 来源 | 示例 |
|------|------|------|
| title | Episode/Entity/Decision 标题 | "修复图片重复显示问题" |
| body | summary + full_content | "将 loop_context 消息角色从 System 改为 User" |
| keywords | 标签/关键词 | "image, loop_context, MessageRole" |
| source | 来源标识 | "session_abc123" |
| tool_names | 涉及的工具 | "read_file, write_file" |
| code_symbols | 代码符号（函数名、结构体名） | "PromptAssembler, build_user_context" |
| file_paths | 文件路径 | "crates/tiangong-core/src/prompt/assembler.rs" |
| error_text | 错误文本 | "413 Request Entity Too Large" |

### 查询示例

```rust
use tantivy::query::*;
use tantivy::collector::TopDocs;

pub fn fulltext_search(
    searcher: &tantivy::Searcher,
    schema: &Schema,
    query_text: &str,
    scope_filter: Option<(&str, &str)>,  // (scope_type, scope_id)
    limit: usize,
) -> Result<Vec<(f32, String)>> {
    let title = schema.get_field("title")?;
    let body = schema.get_field("body")?;
    let keywords = schema.get_field("keywords")?;
    let code_symbols = schema.get_field("code_symbols")?;

    // 多字段 BM25 查询，title 权重更高
    let query_parser = tantivy::query::QueryParser::for_index(
        searcher.index(),
        vec![title, body, keywords, code_symbols],
    );
    let text_query = query_parser.parse_query(query_text)?;

    // 可选 scope 过滤
    let final_query: Box<dyn Query> = if let Some((st, sid)) = scope_filter {
        let scope_type_field = schema.get_field("scope_type")?;
        let scope_id_field = schema.get_field("scope_id")?;
        Box::new(BooleanQuery::new(vec![
            (Occur::Must, text_query),
            (Occur::Must, Box::new(TermQuery::new(
                Term::from_field_text(scope_type_field, st), IndexRecordOption::Basic,
            ))),
            (Occur::Must, Box::new(TermQuery::new(
                Term::from_field_text(scope_id_field, sid), IndexRecordOption::Basic,
            ))),
        ]))
    } else {
        text_query
    };

    let top_docs = searcher.search(&final_query, &TopDocs::with_limit(limit))?;
    let id_field = schema.get_field("id")?;

    let results = top_docs.into_iter()
        .map(|(score, doc_address)| {
            let doc = searcher.doc(doc_address).unwrap();
            let id = doc.get_first(id_field).unwrap().as_text().unwrap().to_string();
            (score, id)
        })
        .collect();

    Ok(results)
}
```

## 向量语义层：Qdrant

### 选型理由

- 支持 dense vector + sparse vector + multi-vector
- 支持 payload filter（按 kind/scope/importance 过滤后检索）
- 支持 hybrid retrieval（dense + sparse 混合）
- 官方 Rust SDK (`qdrant-client`)
- 可嵌入运行（无需独立部署），也可外部部署扩展

### 适用内容

凡是"语义相近但措辞不同"的内容都应进入 Qdrant：

| 向量来源 | 说明 |
|---------|------|
| Episode summary embedding | 任务摘要的语义表示 |
| Decision context embedding | 决策背景的语义表示 |
| Entity description embedding | 实体描述的语义表示 |
| 用户偏好 embedding | Profile 关键句的语义表示 |

### Collection 配置

```rust
use qdrant_client::qdrant::*;

pub async fn create_memory_collection(client: &QdrantClient) -> Result<()> {

        .vectors_config(VectorsConfigBuilder::default()
            .add_named_vector_params(
                "dense",

                ),
            )
        )
    ).await?;

    // 创建 payload 索引，加速过滤
    client.create_field_index(
        "memory", "kind", FieldType::Keyword, None, None,
    ).await?;
    client.create_field_index(
        "memory", "scope_type", FieldType::Keyword, None, None,
    ).await?;
    client.create_field_index(
        "memory", "scope_id", FieldType::Keyword, None, None,
    ).await?;
    client.create_field_index(
        "memory", "importance", FieldType::Float, None, None,
    ).await?;

    Ok(())
}
```

### 查询示例

```rust
pub async fn semantic_search(
    client: &QdrantClient,
    query_embedding: Vec<f32>,
    scope_filter: Option<(&str, &str)>,
    limit: u64,
) -> Result<Vec<(f32, String)>> {
    let mut filter_conditions = vec![
        Condition::matches("status", "active".to_string()),
    ];

    if let Some((scope_type, scope_id)) = scope_filter {
        filter_conditions.push(Condition::matches("scope_type", scope_type.to_string()));
        filter_conditions.push(Condition::matches("scope_id", scope_id.to_string()));
    }

    let results = client.search_points(
        SearchPointsBuilder::new("memory", query_embedding, limit)
            .vector_name("dense")
            .filter(Filter::must(filter_conditions))
            .with_payload(true)
    ).await?;

    let hits = results.result.into_iter()
        .map(|p| (p.score, p.id.unwrap().to_string()))
        .collect();

    Ok(hits)
}
```

### Qdrant 运行模式

| 模式 | 适用场景 | 配置 |
|------|---------|------|
| 嵌入式（in-process） | 桌面应用、本地开发 | Qdrant 以 lib 方式嵌入进程 |
| 外部服务 | Server 部署、多用户 | 独立 Qdrant 实例，通过 gRPC 连接 |

默认使用嵌入式模式，存储在 `~/.tiangong/memory/qdrant/`。

### Embedding 与 Rerank 模型

Embedding 和 Rerank 能力由 `tiangong-llm` 统一提供，通过 `tiangong-core` 的 `ModelCapability::Embedding` 和 `ModelCapability::Rerank` 路由到对应端点。`tiangong-memory` 不自行定义 provider trait，而是依赖 `tiangong-llm` 层的抽象。

#### Embedding

| 阶段 | 方案 | 说明 |
|------|------|------|
| Phase C | API embedding（如 OpenAI `text-embedding-3-small`） | 通过 tiangong-llm `EmbeddingProvider` trait 调用 |
| Phase D | 本地 embedding（如 `ort` + ONNX 模型） | 在 tiangong-llm 中实现本地 provider，离线可用 |

```rust
// tiangong-llm/src/embedding.rs

/// 文本向量化请求
pub struct EmbeddingRequest {
    pub model: String,
    pub input: Vec<String>,
    pub dimensions: Option<u32>,
}

/// 文本向量化响应
pub struct EmbeddingResponse {
    pub model: Option<String>,
    pub data: Vec<EmbeddingData>,
    pub usage: Option<EmbeddingUsage>,
}

/// 文本向量化 provider trait
#[async_trait]
pub trait EmbeddingProvider: Send + Sync {
    async fn embed(&self, req: EmbeddingRequest) -> Result<EmbeddingResponse, LlmError>;
}
```

> tiangong-memory 的 `search/embedding.rs` 不再定义自己的 trait，
> 而是封装对 `tiangong_llm::embedding::EmbeddingProvider` 的调用，
> 提供 Memory 特化的便捷方法（如 `embed_text` 单条文本快捷封装）。

#### Rerank

Rerank 用于双引擎召回后的精排阶段（Stage 4 融合重排），通过 `tiangong-llm` 的 `RerankProvider` trait 调用 rerank 模型（如 Jina/Cohere/BAAI 等）。

| 阶段 | 方案 | 说明 |
|------|------|------|
| Phase C | 规则融合（BM25 + cosine 加权） | 无需 rerank 模型 |
| Phase D | API rerank（如 Jina Reranker） | 通过 tiangong-llm `RerankProvider` trait 调用 |

```rust

## 数据完整性

### 写入流程

记忆写入按顺序执行三层更新：

```rust
pub async fn write_memory(
    &mut self,
    node: &MemoryNode,
    full_content: &str,
    embedding: Option<Vec<f32>>,
) -> Result<()> {
    // 1. SQLite 事务写入（元数据 + 详细数据）
    let tx = self.db.transaction()?;
    self.upsert_node_tx(&tx, node)?;
    self.save_detail_tx(&tx, node, full_content)?;
    tx.commit()?;

    // 2. Tantivy 索引更新
    self.index_node(node, full_content)?;
    self.tantivy_writer.commit()?;

    // 3. Qdrant 向量更新（仅当 embedding 已配置且有向量数据时）
    if let (Some(qdrant), Some(emb)) = (&self.qdrant, embedding) {
        qdrant.upsert_vector(&node.id, emb, node.to_payload()).await?;
    }

    Ok(())
}
```

### 一致性保证

- **SQLite 为主**：SQLite 事务保证元数据写入的原子性
- **索引可重建**：Tantivy 索引和 Qdrant 向量均可从 SQLite 数据重建
- **最终一致**：索引更新失败不影响数据完整性，下次写入或启动时补偿

```rust
/// 从 SQLite 重建所有索引
pub async fn rebuild_all_indexes(&mut self) -> Result<()> {
    let nodes = self.list_all_nodes()?;

    // 重建 Tantivy
    self.tantivy_writer.delete_all_documents()?;
    for node in &nodes {
        let detail = self.load_detail(&node.id)?;
        self.index_node(node, &detail)?;
    }
    self.tantivy_writer.commit()?;

    // 重建 Qdrant（需要重新计算 embedding，仅当 embedding 已配置时）
    if self.qdrant.is_some() {
        // 这是昂贵操作，仅在索引损坏时执行
        tracing::warn!("Qdrant 索引重建需要重新计算 embedding，跳过自动重建");
    }

    Ok(())
}
