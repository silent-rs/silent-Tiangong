# RFC 0005: 适时触发多类型记忆与智能去重

## 背景

当前记忆系统在每个对话轮次结束后统一处理——调用 `build_memory_turn_result()` 构建单个 `TurnResult`，再通过 `run_micro_rumination()` 提取单个 Episode。存在以下问题：

1. **单轮只产出一个记忆**：长对话中多种能力/知识组合只浓缩为一个 Episode，丢失细节
2. **Entity/Decision 延迟到 Meso 反刍**：会话结束后才从 Episode 中提取实体和决策，不及时
3. **无去重**：相似或重复的操作会创建多个 Episode
4. **关联仅基于关键词重叠**：无跨类型关系（Episode→Entity、Decision→Episode 等）

## 目标

- **混合触发**：工具执行后做轻量评估标记候选，轮次结束前统一提炼并去重
- **多类型记忆**：一轮对话能产生 Episode、Entity、Decision、Evidence 等多种类型
- **双重联动**：写入前检索相似记忆去重 + 写入后自动建立关系
- **避免重复**：相似则更新而非新建

## 核心设计

### 1. MemoryCandidate — 工具执行后的轻量提示

工具执行完成后，纯规则评估是否值得记忆，生成 `MemoryCandidate`（无 LLM 调用）：

```rust
pub struct MemoryCandidate {
    pub tool_name: String,
    pub step_index: usize,
    pub hint: String,                              // 一句话描述为什么值得记忆
    pub suggested_kinds: Vec<MemoryCandidateKind>, // 建议的记忆类型
    pub file_path: Option<String>,
    pub url: Option<String>,
    pub result_summary: Option<String>,            // 工具结果摘要（max 240 字符）
    pub success: bool,
}

pub enum MemoryCandidateKind {
    Episode, Entity, Decision, Evidence, UserPreference,
}
```

候选评估规则：

| 工具 | 建议类型 | 触发条件 |
|------|---------|---------|
| `write_file` / `replace_in_file` | Episode + Evidence | 执行成功 |
| `search_code` | Entity | 结果非空 |
| `run_command` | Episode + Decision | 涉及构建/测试 |
| `generate_image` / `generate_video` | Evidence | 执行成功 |
| 其他 | Episode | summary 超过 20 字符 |

### 2. EnhancedTurnResult — 扩展的轮次结果

在原有 `TurnResult` 基础上增加候选列表和对话消息：

```rust
pub struct EnhancedTurnResult {
    // 原有字段保持不变
    pub session_id: String,
    pub turn_id: String,
    pub had_tool_calls: bool,
    pub user_input: String,
    pub summary: String,
    pub tool_calls: Vec<String>,
    pub artifacts: Vec<TurnArtifact>,
    pub workspace_id: Option<String>,
    // 新增
    pub memory_candidates: Vec<MemoryCandidate>,
    pub turn_messages: Vec<TurnMessage>,
}
```

### 3. 统一提炼管道（process_enhanced_micro）

轮次结束前执行：

```
EnhancedTurnResult + 累积的 MemoryCandidate
  → extract_multi_type_memories()     // LLM 或规则提取
    → 检查决策信号 → 内联提取 Decision
    → 检查实体信号 → 内联提取 Entity
    → 始终提取至少一个 Episode
  → write_extraction_with_dedup()      // 去重写入
    → 关键词重叠 ≥ 0.7 + 标题相似度 > 0.6 → 更新已有记忆
    → 否则新建
  → link_written_memories()            // 跨类型关联
    → Episode → Entity: BelongsTo
    → Decision → Episode: LearnedFrom
    → Episode → Episode: RelatedTo（已有逻辑）
  → update_session_injection()
```

### 4. API 变更（MemoryHandle）

```rust
// 新增
pub fn submit_memory_candidate(&self, candidate: MemoryCandidate);
pub fn submit_memory_candidate_blocking(&self, candidate: MemoryCandidate);
pub fn run_enhanced_micro_rumination(&self, turn_result: EnhancedTurnResult);

// 旧接口标记 deprecated
pub fn run_micro_rumination(&self, turn_result: TurnResult);
```

### 5. 调用流程

```
react/engine.rs 工具执行循环:
  工具执行完成 → evaluate_tool_result_for_memory() → MemoryCandidate
  → handle.submit_memory_candidate(candidate)  // fire-and-forget，不阻塞

core/mod.rs worker_loop_async 轮次结束:
  build_enhanced_memory_turn_result() → EnhancedTurnResult
  → handle.run_enhanced_micro_rumination(enhanced)  // 触发统一提炼

tiangong-memory actor:
  累积 candidates + EnhancedTurnResult
  → process_enhanced_micro()
  → 多类型提取 + 去重 + 跨类型关联 + 注入更新
```

## 实施阶段

### Phase 1: 新类型 + API 骨架（无行为变化）
添加所有新数据结构、命令变体和 Handle 方法，旧逻辑不变。

### Phase 2: 候选评估（tiangong-core 侧）
实现 `evaluate_tool_result_for_memory`，在工具执行循环中提交候选。

### Phase 3: 增强版 Micro 反刍管道（tiangong-memory 侧）
实现 `process_enhanced_micro`、多类型提取、去重和跨类型关联。

### Phase 4: Inline Entity/Decision 提取
轻量 LLM 提示从单轮中即时提取 Entity/Decision。

### Phase 5: 集成验证
长对话多类型记忆、去重、关联、向后兼容性测试。
